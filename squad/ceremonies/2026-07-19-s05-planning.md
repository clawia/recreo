# [Sprint s05] Planning — 2026-07-19

- Sprint : s05 ; animé par Sofia ; présents : Camille, Marc, Léa, Théo, Yanis.

## Objectif de sprint
Introduire un vrai **mode session** et enrichir l'anglais. Déclenché par la démo s04 : « je n'ai
eu que 6 mots différents sur 20 questions ; je veux des sessions de 50 questions sans redemander
un mot déjà bien répondu ».

## Stories

### US-s05-1 — Session de N questions sans doublon des réponses réussies (mécanique)
> En tant qu'élève, je joue une session d'un nombre choisi de questions ; un item que j'ai réussi
> ne revient pas, mais un item raté peut réapparaître ; à la fin, je vois mon score.

Critères d'acceptation :
- [ ] La session a une **longueur cible** (nombre de questions), **réglable par un adulte**
      (défaut 20), bornée (5..50, et jamais au-delà du nombre d'items distincts disponibles pour
      un jeu à liste finie).
- [ ] Un item **réussi n'est plus reproposé** dans la session ; un item **raté peut revenir**.
- [ ] La session se **termine** quand la cible est atteinte (ou quand le vivier distinct est
      épuisé) : écran de fin avec **score X / Y** et bouton rejouer / retour.
- [ ] `BanditManchotMechanic` peut évoluer, mais **le découplage mécanique/contenu est préservé**
      (ArchUnit vert) : la mécanique demande au `ContentGenerator` un item en excluant des clés.

### US-s05-2 — Enrichir le vocabulaire anglais (≥ 50 mots)
> En tant qu'élève, j'ai assez de mots pour une session de 50 sans doublon.

Critères d'acceptation :
- [ ] `AnglaisLexiqueGenerator` porte **≥ 50 paires FR→EN** vérifiées (thèmes courants CM1).
- [ ] Une session de 50 questions bien répondues ne montre jamais deux fois le même mot.

## Cadrage technique (Théo) — ADR-0006 pressenti
- **Modèle de session** : `GameSession` gagne `questionsTarget`, `answered`, et l'ensemble des
  **clés maîtrisées** (items réussis). Documenter délibérément ce modèle (répond à l'alerte
  « enflure de GameSession » de la rétro s03).
- **Identité d'item** : ajouter une **clé de contenu** à `Item` (ex. dérivée des `reelSymbols`)
  pour reconnaître un item déjà vu, sans que la mécanique n'interprète le contenu.
- **Contrat générateur** : `next(random, exclureClés)` ; l'ancien `next(random)` délègue. Vivier
  fini épuisé → signal d'épuisement → fin de session. Générateurs combinatoires (calcul) :
  exclusion best-effort.

## Affectations

- **Marc** : évolution `GameSession`/`GameMechanic`/`ContentGenerator` (exclusion + fin de session) ;

- **Léa** : écran de **fin de session** (score) + réglage « nombre de questions » dans l'écran de

- **Yanis** : tests — pas de doublon des réussis sur une session complète ; item raté peut revenir ;
  fin à la cible / à l'épuisement ; anglais ≥ 50 sans doublon sur 50 ; existants mis à jour.
- **Camille** : bornes (5..50), fiche(s)/matrice si impact ; valide le principe pédagogique
  (réussite = retrait, échec = re-test) — proche d'une répétition espacée simple.
