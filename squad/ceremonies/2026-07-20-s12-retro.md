# [Sprint s12] Rétro — 2026-07-20

- Sprint : s12 ; animé par Sofia ; présents : toute la squad.

## Ce qui a bien marché
- **Orchestration par sous-agents** : 1 agent d'archi (conception sur code réel) + 4 agents
  d'implémentation en parallèle sur fichiers disjoints → **build vert du premier coup**. Le secret :
  poser le **cœur partagé** (le variant `Move`) AVANT de fan-out, et figer le **contrat POST** pour
  que le front et le back avancent sans se parler.
- **Abstraction qui tient** : ajouter une interaction radicalement différente (arrangement) n'a pas
  cassé l'isolation des mécaniques ni le moteur partagé — variant `Move` + moteur agnostique.
- **Zéro dépendance** : drag-and-drop HTML5 natif → fat jar intact, pas de build Node.

## Ce qui a moins bien marché / vigilance
- **Signature `gameCatalog` à 4 args** : cassait 5 tests appelant l'ancienne signature (pas 1 seul
  comme estimé) — corrigé en lot, mais rappelle de grep TOUS les appelants avant de changer une
  signature partagée.
- **Accessibilité tactile** : le drag-and-drop natif est le point faible (mobile/doigt) — repli
  « taper pour placer » à prévoir si la démo le réclame (noté ADR-0013 / DEC-0008).
- **Sous-agents sans build** : on leur a interdit `mvn` (builds concurrents) → leur code n'est
  self-vérifié qu'à l'intégration. Acceptable ici (spec précise), mais l'orchestrateur porte la
  responsabilité de la compilation.
