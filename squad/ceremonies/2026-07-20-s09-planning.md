## Objectif de sprint
**Externaliser le contenu (DEC-0006)** — 1re tranche décidée avec l'utilisatrice : la **famille
quiz** (7 jeux), la plus homogène. Le contenu quitte le code (sous-classes Java) pour des
**fichiers YAML éditables**, chargés et validés au démarrage. But produit : l'utilisatrice édite
le contenu **sans dev ni recompilation**.

## US-s09 — Externalisation du contenu quiz
- **ADR-0009** (Théo) : contenu quiz dans `content/quiz/*.yml` ; chargement + validation dans
  `bootstrap` (`QuizPackLoader`, scan `classpath*:content/quiz/*.yml`) ; le domaine n'expose qu'un
  `QuizGenerator` générique. Clean Architecture préservée (domaine ne lit aucun fichier), ArchUnit 5/5.
- **7 fichiers YAML** (questionner le monde CP ; sciences/histoire/géo CM1 ; EMC CP/CM1 ; vrai-faux
  sciences) reprenant fidèlement le contenu existant (mêmes entryId/gameKey/titres → zéro régression).
- **Suppression** des 7 sous-classes `QuizGenerator`.
- **Validation au démarrage** : champs requis, ≥1 question, distracteurs distincts ≠ bonne, pas de
  doublon ; fichier incohérent → boot échoue avec message.
- **Guide** d'édition pour l'utilisatrice (`squad/programme/CONTENU-editable.md`).
